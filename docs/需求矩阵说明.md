# 产品需求 — 统一宽表结构

三阶段（BRD → 功能 → 用户故事）**共用一个文件、一张主表**，按列递进填写，用 ID 链保证无遗漏。

## 文件

- 用户自定路径；编排时 **@ 该文件** 即可。
- 建议文件名含「需求矩阵」或项目名，**不强制** `BRD.md` 等。

## 主表：需求矩阵

一张 Markdown 宽表（或 CSV），**每一行 = 一条可追溯链路的最细粒度行**（最终落到「一个用户故事」一行；前期可暂时空着故事列）。

### 列定义（固定顺序，不可调序）

| 列序 | 列名 | 说明 | BRD 阶段 | 功能 阶段 | 故事 阶段 |
|------|------|------|:--------:|:---------:|:---------:|
| 1 | 场景ID | 主流程条线，如 MF-01 | 必填 | 继承 | 继承 |
| 2 | 页面ID | 如 P-01 | 必填 | 继承 | 继承 |
| 3 | 功能ID | 如 P01-F01 | 空 | 必填 | 继承 |
| 4 | 用户故事ID | 如 US-001 | 空 | 空 | 必填 |
| 5 | 场景说明 | 流程名/一句话 | 必填 | 可空 | 可空 |
| 6 | 主流程步骤 | 如 MF-01 第2步 | 建议填 | 继承 | 继承 |
| 7 | 页面名称 | 展示名 | 必填 | 继承 | 继承 |
| 8 | 功能名称 | 短标题 | 空 | 必填 | 继承 |
| 9 | 功能说明 | 用户可完成什么 | 空 | 必填 | 继承 |
| 10 | 用户故事 | 作为…我想要…以便… | 空 | 空 | 必填 |
| 11 | 备注 | 分支、后台步骤等 | 选填 | 选填 | 选填 |

**核心 ID 列（1～4）** 用于阶段间 mapping；**5～11** 为各阶段写入的正文。

### 行怎么长（防遗漏）

```text
BRD 阶段：
  每个「场景ID × 页面ID × 主流程步骤」至少 1 行
  功能ID、用户故事ID 留空

功能 阶段：
  在已有行上拆分/新增行，使每个「功能ID」有行
  同一 场景+页面 下多个功能 → 多行（页面ID、场景ID 重复）
  用户故事ID 仍空

故事 阶段：
  每个「功能ID」至少 1 行带 用户故事ID + 用户故事列
  多个故事同一功能 → 多行（功能ID 重复）
```

### 无遗漏自检（任一阶段结束必做）

| 检查 | 规则 |
|------|------|
| 场景 | 每个场景ID 至少 1 行 |
| 页面 | 每个页面ID 至少 1 行，且属于某场景ID |
| 功能 | 每个功能ID 至少 1 行，且 (场景ID,页面ID) 与 BRD 一致 |
| 故事 | 每个功能ID 至少 1 行 用户故事ID 非空 |
| ID 级联 | 不允许出现「有故事无功能」「有功能无页面」「有页面无场景」 |
