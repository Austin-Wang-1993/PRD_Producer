# BRD 输出契约 — docs/BRD.md

编写 `docs/BRD.md` 时必须满足本契约。质检以 `prompts/qa/v1/checklists/brd.md` 为准。

---

## 文件路径

`docs/BRD.md`

## 必须章节（顺序固定）

```markdown
# BRD — {产品/研究名称}

| 字段 | 内容 |
|------|------|
| 文档版本 | x.y |
| 状态 | 草案 / 待确认 / 已定稿 |
| 产品类型 | 一句话 |

## 1. 背景与目标
### 1.1 需求背景
### 1.2 产品目标（可用表格，≥3 条目标）
### 1.3 成功指标（业务向，可衡量）
### 1.4 非目标（Out of scope）≥3 条

## 2. 用户与场景
（角色表 + 场景表 ≥3 行）

## 3. 业务范围
### 3.1 In scope
### 3.2 Out of scope

## 4. 业务主流程（商业/业务视角）
（编号步骤，角色与业务结果）

## 5. 用户主流程（产品内 · 详细）★ 核心
### 5.1 流程总览
（入口 → … → 核心目标完成）
### 5.2 主路径（逐步）
| 步骤 | 用户意图 | 页面/触点 | 系统行为 | 备注 |
（≥5 行，每行页面/触点非空）
### 5.3 分支与异常路径
| 分支ID | 触发条件 | 路径差异 | 结束状态 |
（≥2 行，或明确「本期无分支」+ 理由）
### 5.4 页面/触点索引
| 页面/触点ID | 名称 | 首次出现于步骤 | 说明 |
（≥1 行，ID 与 5.2 一致）

## 6. 业务规则与约束
## 7. 成功指标（产品内，可与 1.3 呼应）
## 8. 待验证假设 / 待决问题
## 9. 变更记录
```

## §5 硬性指标（编写自检）

| 指标 | 阈值 |
|------|------|
| 主路径步骤 | ≥ 5 |
| 每步页面/触点 | 100% 填写，禁止 TBD |
| 分支 | ≥ 2 或声明无分支 |
| 5.4 索引 | 覆盖 5.2 中出现的所有页面/触点 ID |
| 可枚举性 | 评审者能仅凭 §5 列出预期页面的 80%+ |

## 页面/触点 ID 命名建议

- 格式：`P-NN` 或 `P-NN-子`（如 P-02、P-03）
- 全文一致，供功能清单直接引用

## 修订规则

- 用户确认前：小改 +0.1，结构重做 +1.0
- 用户确认后改动：在 §9 记录，并提示「下游文档可能过期」
