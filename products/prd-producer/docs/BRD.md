# BRD — PRD Producer（前端产品研究流水线工具）

| 字段 | 内容 |
|------|------|
| 文档版本 | 1.0 |
| 状态 | 草案（产品定义用） |
| 产品类型 | 本地/自托管 Web 应用 + 后端编排 + GitHub 存储 |

---

## 1. 背景与目标

### 1.1 需求背景

- **使用者**：独立做**前端产品研究**的 solo 从业者（产品负责人兼设计/协调角色），无协作评审流程。
- **现状痛点**：
  - 与通用 AI 聊天产出的 PRD **结构不稳定**，难以直接支撑页面枚举与用户故事拆解。
  - 澄清、写文档、质检、修改散落在对话中，**无法回溯**，也不利于后续 AI 写代码。
  - 希望在**一个产品内**完成：业务澄清 → BRD → 页面&功能清单 → 用户故事清单，且每份文档**可质检、可确认、可版本化**。
- **约束**：
  - 交付物最终存放在 **GitHub 仓库**（每个研究项目一个 repo）。
  - **仅当 BRD 首次经用户确认通过后**，才允许「授权创建 GitHub 仓库」。
  - 三个生产智能体（BRD / 功能清单 / 用户故事）**互相解耦**，由用户主动切换与触发；允许「用户故事聊到一半回去改 BRD」。

### 1.2 产品目标

| 目标 | 说明 |
|------|------|
| **G1 结构化** | 固定三份交付物格式，尤其 BRD 内含**详细用户主流程**，支撑全量页面与功能枚举。 |
| **G2 质量可控** | 每份文档均经**质检智能体**检查；编写智能体无法回答时需用户协助；**用户确认**后才算定稿。 |
| **G3 灵活编排** | 用户主导切换智能体，非强制单线流水线；对上游变更给出过期提示。 |
| **G4 可追溯** | 全过程日志（对话、质检、确认、建库）可查询；观察智能体独立记录改进点。 |
| **G5 可衔接实现** | 三份文档独立文件，暂不合并，供后续 AI 或人工开发使用。 |

### 1.3 成功指标（业务向）

- 单个研究项目从建项到三份文档均「已定稿」，**平均人工确认轮次可统计**（目标：BRD ≤3 轮确认）。
- 功能清单中**页面与 BRD 主流程步骤映射无孤儿**（质检通过率）。
- 用户故事 100% 可回溯到「页面 + 功能 ID + 流程步骤」。

### 1.4 非目标（Out of scope · 本期）

- 多人协作、评论、审批流。
- 在线富文本协同编辑、Figma 导入。
- 自动合并三份文档为一份 PRD。
- 内置代码生成 IDE（仅交付需求文档至 GitHub）。
- Cursor / 其它 IDE 插件（后续可选，本期不做）。

## 2. 用户与场景

| 用户角色 | 定义 |
|----------|------|
| **研究者（唯一用户）** | 本人，创建项目、与智能体澄清、确认文档、授权建库、查阅日志与观察记录。 |

| 场景 ID | 场景 | 频率 |
|---------|------|------|
| S1 | 有一个新的前端产品想法，从零开始研究 | 高 |
| S2 | BRD 写完后发现主流程漏分支，回去改 BRD 再续聊用户故事 | 中 |
| S3 | 质检提出格式问题，智能体自行修复 | 高 |
| S4 | 质检问题涉及业务抉择，智能体请求用户协助后再回复质检 | 中 |
| S5 | 三份文档定稿后，到 GitHub 查看/交给下游 AI 写代码 | 高 |

## 3. 业务范围

### 3.1 In scope

- 项目 CRUD、按文档维度的状态机。
- 三个解耦生产智能体 + 一个质检智能体 + 一个观察智能体（旁路）。
- 每份文档：澄清 → 编写 → 质检环 → 用户确认 → 定稿。
- BRD 确认后「授权创建 GitHub」及字段预览。
- 过程日志时间线 + 筛选；观察记录独立查看。
- 建库后所有产物 push 至项目 GitHub 仓库。

### 3.2 Out of scope

- 见 1.4。

---

## 4. 业务主流程（业务视角）

1. 用户产生「前端产品研究」需求。
2. 在工具内**新建项目**，开始 BRD 澄清。
3. 形成符合格式的 BRD（含详细用户主流程），经质检与用户确认。
4. 用户**授权**创建 GitHub 仓库，系统将 BRD 等初始内容入库。
5. 用户按需唤起**功能清单**智能体：澄清 → 出稿 → 质检 → 用户确认 → 定稿入库。
6. 用户按需唤起**用户故事**智能体：同上。
7. 用户可在任意时刻切换智能体修改上游文档；系统提示下游文档可能过期。
8. 三份文档均在 GitHub 定稿后，项目可标记为完成；用户导出或在外部使用。

## 5. 用户主流程（产品内 · 详细）★

### 5.1 流程总览

```text
入口(项目列表) → 新建项目 → [BRD 轨] 澄清→编写→质检→用户确认 → 授权建库
    → [功能清单轨] 用户触发 → 澄清→编写→质检→用户确认 → 定稿
    → [用户故事轨] 用户触发 → 澄清→编写→质检→用户确认 → 定稿
    → 完成；全程可查日志/观察，任意时刻可切换轨道修改上游
```

### 5.2 主路径（逐步）

| 步骤 | 用户意图 | 页面/触点 | 系统行为 | 备注 |
|------|----------|-----------|----------|------|
| 1 | 开始新研究 | P-01 项目列表 | 展示项目及每文档状态 | |
| 2 | 创建项目 | P-01 → 弹窗/表单 | 创建项目记录，状态初始化；**不创建 GitHub** | |
| 3 | 与 BRD 智能体澄清 | P-02 工作台·BRD | 对话、记笔记；可暂停离开 | 默认进入 BRD |
| 4 | 等待 BRD 成稿 | P-02 | 智能体编写 BRD；通知「开始编写」类消息 | |
| 5 | 驱动 BRD 质检 | P-02 | 进入质检；系统对话（质检↔BRD）；必要时向用户发起协助 | 用户不填质检回复表 |
| 6 | 审阅 BRD | P-03 BRD 确认 | 展示全文，§5 高亮；通过/修改/继续澄清 | 循环直至通过 |
| 7 | 授权建库 | P-04 授权建库 | 展示 repo 名/描述预览；调用 GitHub API；成功通知+链接 | **仅步骤6通过后可见** |
| 8 | 做功能清单 | P-02·功能清单 Tab | 用户主动切换；读最新 BRD；澄清→编写→质检→确认 | 软依赖 BRD |
| 9 | 做用户故事 | P-02·用户故事 Tab | 同上；读 BRD+功能清单 | 软依赖清单 |
| 10 | 改 BRD | P-02·BRD | 修订→再质检→再确认；版本+1；提示下游过期 | 解耦切换 |
| 11 | 查看过程 | P-02·日志 Tab | 时间线筛选 | |
| 12 | 查看观察 | P-02·观察 Tab | 只读观察智能体记录 | 不参与链路 |
| 13 | 在 GitHub 使用定稿 | 外链 GitHub | 只读/下载三份 md | |

### 5.3 分支与异常路径

| 分支ID | 触发条件 | 路径差异 | 结束状态 |
|--------|----------|----------|----------|
| B1 | 用户要求修改 BRD（确认页） | 回到步骤3或4，更新稿后再质检、再确认 | 回到步骤6 |
| B2 | 质检无法回答 | 编写智能体发起「质检协助」；用户回复后继续质检 | 步骤5继续 |
| B3 | 未建库即想定稿功能清单 | 内容可缓存在应用存储；定稿 push 需 repo 已存在（或提示先完成步骤7） | 等待建库 |
| B4 | 建库 API 失败 | 展示错误（重名/权限）；用户修改授权参数或重试 | 停留 P-04 |
| B5 | 上游 BRD 变更且下游已定稿 | 橙条提示过期；建议重新确认功能清单/用户故事 | 用户决定 |

## 6. 业务规则与约束

- **R1**：每个项目对应**至多一个** GitHub 仓库，创建于 BRD 首次用户确认通过且用户授权之后。
- **R2**：三份文档定稿版本递增；GitHub 每次定稿/重要节点产生 commit。
- **R3**：质检与编写智能体之间的对话记入 `system/qa-rounds/`，对用户默认折叠展示。
- **R4**：观察智能体**不得**改变文档状态或调用生产智能体。
- **R5**：BRD 第 5 章未满足「详细用户主流程」最低标准时，质检**不得**放行。

---

## 7. 成功指标（产品内）

- 新建项目 → BRD 确认 → 建库成功路径 **≤15 分钟**（不含澄清内容耗时，仅系统能力）。
- 日志事件类型覆盖：用户消息、编写、质检轮次、用户确认、建库、escalation 等 **≥12 种**。
